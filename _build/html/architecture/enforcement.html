Enforcement Model

dbguard can observe every query and block the ones you connect through the proxy. Understanding which plane does which is the key to deploying it correctly.

Detection plane: detect, audit, react

The eBPF detection plane fires after the database has begun parsing the statement. It always audits the verdict. What it does beyond auditing depends on ebpf.drop_enabled:

drop_enabled

Behaviour on a denied query

false (default)

Detect + audit only. The event records allowed: false and the matched rule; the query still runs. Safe for roll-out and observation.

true

Reactive enforcement. In addition to auditing, the daemon may terminate the offending backend and quarantine the source (below).

Important

The detection plane is reactive, not synchronous. The uprobe fires at parse time, the event travels the ring buffer and pipeline, and only then does the enforcement loop act - microseconds later. A sub-millisecond query (SELECT 1 UNION …) can finish and return before the action lands. A long-running query (SELECT pg_sleep(5)) is interrupted cleanly. For guaranteed blocking of any statement, use the inline proxy.

Reactive actions (when drop_enabled: true)

Action

Mechanism

Terminate session

SIGTERM to the PostgreSQL backend that ran the query - ends just that one session. dbguard refuses to signal a threaded mysqld server (that would drop every connection); MySQL denials are audited/alerted on this plane.

Quarantine source

Add the client IP to a kernel quarantine map so subsequent packets are dropped for a TTL (requires the cgroup/XDP drop program to load on your kernel).

Drop / RST

cgroup_skb packet drop or TCP RST injection, where the corresponding kernel program is available.

Enforcement plane: synchronous inline proxy

The inline proxy is a protocol-aware man-in-the-middle for the connections you route through it. It evaluates policy before forwarding, so a denied statement is never sent to the database - the client gets a native protocol ERROR:

ERROR:  dbguard: query blocked by policy (rule sqli.union)

Because the decision happens on the wire, it is deterministic for every statement, fast or slow. This is the plane to put in front of application connections you want to hard-block. It is protocol-aware for both PostgreSQL and MySQL (handshake, auth pass-through, COM_QUERY / simple-query framing, TLS decline so plaintext can be inspected).

Note

The proxy declines TLS (replies to the client’s SSLRequest so it proceeds in plaintext) in order to inspect statements - the correct, safe default for a local enforcement proxy. For production TLS you terminate TLS at the proxy.
